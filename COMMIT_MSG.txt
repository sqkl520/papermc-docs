1. b0 不能取 git show HEAD:assets/* —— HEAD f3ebbfc 的 site.css blob 2dfd39c4 与工作树
   逐字节相同，照做会让 b0 等同于 new、批 1 贡献恒为 0。b0 必须取 fcdf3e1（blob a7283ad4）

## 四项裁决（其中两项推翻我此前的判断）
1. 批 1 对列宽贡献 = 0（60 格实测确认，new 与 b0 的 artW/行宽 100% 相同）；
   归因铁律：凡涉及列宽只能拿 old 比
2. 断崖不是 1025 单点，是 1023->1025 两级台阶（-279 / -259，共 -536px），
   成因是 min-width:1024 让侧栏进场但 TOC 未进 -> 1024 死区。
   推翻我此前「>=1280 常驻」的裁决：实测证明单搬 TOC 断点无效，
   必须让侧栏与 TOC 断点重合；绑 1200 得单级 -340px 且 1024 死区消失（artW 693->949），
   优于绑 1280（-260px 但 1025-1279 全退化为单栏）。新裁决：侧栏 + TOC 同绑 1200
3. 代码 strut 数值分歧已裁决：实际行推进是 [22,21] 混合值（中位 22），不是单一数。
   页高变化以实测为准 dialogs -755 / particles -718 / worldcfg -99。
   三方一致（old=b0=new=24.8）为存量缺陷。反证：让 code 继承字号会让 particles
   横滚 4/46 恶化到 11/46，正确修法是给 pre 设字号
4. 批 2 的选择器必须从 .article > :is(...) 改为 .article p{max-width:40rem}：
   直接子选择器有致命盲区（worldcfg 直接子 p = 0，31 个段落全在 ul/alert 内），
   且限宽 ul 会把 worldcfg 代码块从 874.81 压到 566px（-309px）而横滚数仍 0/5
   导致只看横滚会漏掉该回归。改成只限叶段落后：行宽 98 降到 74 字符、
   代码块原宽、横滚全不变、左边缘对齐
